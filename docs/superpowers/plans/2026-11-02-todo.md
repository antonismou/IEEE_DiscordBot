# Officer To-Do and Reminders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Officers manage one shared team task list and get reminders (2d / 1d / 1h / due / overdue) by DM and/or the officers' channel (always visible to the whole team), with free-standing reminders, DM buttons, repeating tasks and a pinned board. Officers only, hidden from others.

**Architecture:** A new `bot/todo/` package holds pure, testable pieces (date parser, repo, reminder scheduling/delivery service, renderers); `bot/cogs/todo.py` wires them to Discord (one `/todo` command group, a 30 s `tasks.loop`, persistent `DynamicItem` buttons). Delivery is done through an injected `send` callback so the service is tested without Discord.

**Tech Stack:** Python 3.12, discord.py 2.7, SQLite (existing). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-02-todo-design.md`

## Global Constraints

- Officers only: every `/todo` subcommand has `@officer_only()`; the group has `default_permissions=discord.Permissions(administrator=True)` and `guild_only=True`.
- There are no personal tasks: every task is shared. Any officer can view, edit, complete, assign and delete any task. Task titles are posted to the private `todo-reminders` / `todo-board` channels; the audit log gets ids only.
- Announcements (created / assigned / done / deleted) and reminders are posted to the `todo-reminders` channel when it is bound. Default `notify`/`delivery` is `both`.
- Reminder offsets: `2d`, `1d`, `1h` before; `due` at the due time; `overdue` at due + 1d. Rows already in the past are not created.
- Delivery is at-most-once (mark `sent_at` before sending). Allowed mentions are limited to the single intended user or the Officer role. Never `@everyone`.
- Timezone `Europe/Athens` for parsing; display with Discord timestamps `<t:UNIX:f>` / `<t:UNIX:R>`.
- Limits: title 100, description 500 (use `bot.validation.clean_text`), 500 open tasks, 25 pending free-standing reminders per officer.
- Time is injectable: functions take `now: datetime` (UTC-aware); tests never sleep.
- Repo style: `from __future__ import annotations`, repos take `conn`, tests use the `conn` fixture and `tests/fakes.py`, friendly ephemeral refusals, no tracebacks to users.
- Do not commit anything unless the user asks. (Task steps say "Commit" for the executing workflow; follow the user's current instruction at execution time.)

## Review Focus

- A non-officer reaching any task, command, button or channel (all are officer-gated; the bot warns if the channels are visible to @everyone).
- Reminder sent twice, or a burst after a restart; late-catch-up dropping rules.
- Reassign / edit due / done / delete correctly removing unsent reminders and recreating them.
- DM button clicks after a restart, from someone who is no longer an officer, and on a task already done or deleted.
- `/forget-me` and `/member delete` removing that user's reminders and unassigning/anonymising them on tasks.
- Repeat: month-end clamping, repeating task with no due date rejected, next due always in the future.

**Interfaces:**

- `service.py`:
  - `OFFSETS = (("2d", timedelta(days=2)), ("1d", timedelta(days=1)), ("1h", timedelta(hours=1)), ("due", timedelta(0)), ("overdue", -timedelta(days=1)))`

Exceptions from `send` are logged and swallowed (one failure must not stop the others). Returns number sent.
